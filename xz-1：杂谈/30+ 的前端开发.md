# 关于 30+ 的前端开发的一些思考

## 一、残酷现状

一个可能比较残酷的现状是，真正能够在这个年龄阶段，做到与 30 岁前端有所不同的，并不多。甚至，由于技术方案的不断迭代和变迁，能做到技术比同时段 30 岁更强的，都很少。反而是更多的人在工作的过程中，深感自己跟不上前端发展的节奏，新的方案一层套一层，倍感自己落后于技术前沿而焦虑。

因为这里有一个比较残酷的真相就是：自然而然的情况之下，工作经验的积累，并不能让我们变得更强

为什么呢？

因为，**大多数情况下，重复一定是工作的本质。**

一般来说，我们在进入一个团队的前半年，会觉得自己有比较大的技术上面的提高，但是一旦熟悉了这个团队这套开发流程之后，就会进入一个舒适区，开发内容开始变得重复且枯燥，增删改查、引用成熟解决方案大概率会成为工作的常态

这也是许多人，在离开这个团队之后，找工作很困难的核心原因之一，许多人会觉得自己没有项目亮点，不知道怎么去聊自己的项目才会显得出彩。

随着时间的积累，你就会慢慢发现，**工作时长，完全无法转化为等价的工作经验。**

## 二、有所不同？

有一种人非常受大厂的欢迎：**具备主观能动性的人**，有的团队对这种品质的要求甚至还要在技术能力之上。而给自己的职业生涯在不同的阶段制定对应的职业规划或者职业目标，是主观能动性的表层体现之一。

好的面试官在面试的时候，总会用各种旁敲侧击的方式来判断候选人是否具备主动能动性。因此，跟你聊你过往的工作或者项目经历与你的职业规划，几乎是逃不掉的话题。

> 甚至我们在做团队管理的时候，也会想尽各种办法去调动团队成员的主观能动性，只是一些比较菜的管理者在操作方式上存在问题，往往会被团队成员认为是：洗脑或者 PUA

## 三、应该有哪些不同

许多程序员，有一个简单的思维模型：干得越久，技术能力就会越强，职业发展就会越顺利。那我不停的研究技术不就完事了。因此很多人比较简单的想法是，自己要是能干一辈子一线开发就好了。

如果突然有一天，他发现真实世界不是这个样子的，程序员似乎到了某个年龄段会被淘汰？他就会觉得这个行业不健康。

于是，他甚至连学技术的动力都没了，摆烂成为了很大一部分人的选择。甚至还会在各种场合以吐槽的形式来传播自己的焦虑。

这个简单的思维模型有两个漏洞

一个是，**干得越久，你的技术能力不一定越强。甚至是大概率不会越强。**

另外一个是，随着年龄的增长，对工作内容更加熟悉，**你会越来越讨厌被别人指挥，你甚至会觉得别人的指挥很 sb。但是一线开发，就是被别人指挥，你的工作产出结果，就是被别人评价。** 这是一个我们无法逃避的悖论。

被人指挥和评价，就难免受气。

所以，当你的职业生涯发展到后半段，你就会发现，这个思维模型不仅简单，还存在重大的误区。许多老职场人，在职场里，会显得非常非常的别扭。他看透了公司的各种话术和套路，心里无法跟公司文化达成一致的协调，但是一线开发又一定是公司文化的必争之地。传统的加油、打气、洗脑、画饼、讲道理、上强度、给压力等等基本上全都是冲着一线开发去的。

所以有的人在工作中会感受到巨大的痛苦。自己辛辛苦苦的写代码，加班，完了还要被领导骂，被领导言语威胁，甚至还要莫名其妙的背锅。实际上，这就是一线开发的常态。

因此，从这个角度反过来看，一个健康发展的 40 岁职场人，和 30 岁相比，最大的不同就是，他懂得如何有效的掌握职场中的话语权。

许多小伙伴会在各种场合抱怨团队垃圾，吐槽领导 sb，往往其核心的本质原因，就是自己无法掌握话语权导致的。

例如在前端方向，对于技术方案之争。许多经验丰富的前辈会在社交平台发文去论述 React 好还是 Vue 好。实际上这是一个很有价值的问题。但是这里有一个很有意思的现象是：由于讨论的比较多了，许多读者会反感这类讨论，认为毫无意义，没有必要，觉得是在拉踩，谁给钱我就用谁等等。

但是，真实的职场真的不是这类中立派想的这样，认为技术方案的选型之争只存在于 React 开发者和 Vue 开发者之间。在职场里，有的时候他实际上涉及到了话语权之争，甚至职业发展之争。

这个时候，我们作为开发人员的专业性就会被老板长期质疑，在后续的工作中，伴随而来的就是话语权的严重丢失，在这个团队的发展就会处处受限。

因此，在这个基础场景之下，如果想要维持好自己的专业技术形象，我们就必须从技术的角度，正面否定老板的观点：Vue 开发效率并不是更高、Vue 的性能也并不是更好，我们的技术选型没有做错。

没得选。这不是技术之争，而是话语权之争。

又或者，有的团队在面临技术团队合并的情况之下，一个团队用 Vue，一个团队用 React，那如果上面要求统一技术栈，你又应该如何应对？

所以我们一定要明确：技术选型之争，在职场里，很多时候是话语权和利益之争，而不管你是 React 开发，还是 Vue 开发，你都应该掌握充分的理由去确保自己的选择是经过深思熟虑的结果

而合格的 40 岁职场人，最大的区别就是，懂得如何培养自己的各方面的能力，让自己在职场话语权之争中，取得优势。

这就是我们要做职业规划的重要目的。作为开发者，技术能力一定是你职业规划中的重要一环，但也一定不是全部。

> 当然，其他的许多能力，也是建立在技术能力的基础之上，例如我们说沟通能力要强，但实际上我们更多的场景是基于技术讨论的沟通能力

## 四、一个更重要的区别：角色转换

30 岁我们的发展目标是如何成为一个更好的执行者。

通常这个时候我们的技术能力达到了一个新的高度，在技术深度上达到了一个比较好的水平，具备比较强的技术攻坚能力。擅长快速实现需求，修复复杂 bug，能够在现有技术架构下面找到更好的方案。

但是，再往后的发展过程中，我们要完成一个很重要的蜕变，就是：**从能解决问题，进阶到能定义问题。**

什么意思呢，我们接着上面那个例子往下聊。现在我们由于团队架构的调整，两个团队要进行合并，一个团队用 Vue，一个团队用 React，这个时候，老板顺势提出要求：要实现前端团队的技术栈统一

一个好的执行者的思维方式是：如何把 Vue 项目重构成 React 项目，或者把 React 项目重构成 Vue 项目。

而定义问题的表现则是：首先思考是否有统一技术栈的必要性？ 统一技术栈有收益，但是收入是否足够高？

因此，你会大量思考和评估统一技术栈带来的好处和团队为此付出的成本，不统一技术栈的好处和成本，然后在此基础之上说服老板按照你的想法来做决策。

因为在开发或者前端开发这一侧，你应该是公司的绝对权威。老板可以在初期提出自己不成熟的想法和观点，但是你必须要在论证阶段提出更加成熟的建议和思考。

**所以，一个好的技术 Leader 甚至可以让老板变得越来越专业，越来越成熟。**

很明显，成熟的定义问题，往往能让整个团队减少大量的无效工作压力。

因此，在职业发展的过程中，我们要有意识的去培养自己具备掌握技术决策权的能力。越早具备这个能力，那么对于我们个人而言，就会越受益。

不过，这个角色的转变说起来很容易，但是做起来则很困难。因为在团队沟通过程中，技术沟通往往暗藏着私心，而不是纯粹的技术讨论：例如一个复杂的逻辑到底是前端做还是后端做，有的时候双方都会推给对方，因为糟心事儿都不想做，但是表面上却又要从技术的角度去辩论到底谁做有什么风险，哪里做更安全等等

而大多数前端开发，往往会在这样的技术沟通中，处于弱势。从而在团队中失去话语权。这，就是为什么很多前端感觉自己在公司没什么存在感的核心原因之一。

这也是一些后端开发，会在老板面前反复强调，前端很简单，我们后端也可以写前端页面的核心原因之一。

有的比较惨的前端开发，甚至深受困扰，说不过后端，辩不过老板，扯不过产品，甚至连 UI 和测试都能踩前端一脚。妥妥受气包加小透明

## 五、从技术深度到技术广度

这里有一个很重要的认知误区，认为技术深度更难达到，而技术广度则相对比较容易。

实际上并不是这样。在字节的招聘要求中，对 3 ~ 5 年工作经验的候选人，有技术深度的要求。

而对 5 年以上的候选人，则会新增一个技术广度的要求。

因为**这里的技术广度，指的是多个技术深度。**

所以一定要注意，技术广度，并不是对某一个方向浅尝辄止，而是能够在多个方向，进行深入的探讨

而如果我们想要具备多个技术深度，则就要求我们在成长的过程中，凝练出一套自己的高效学习方法，让我们可以在别的方向上，也可以快速达到一定的水平。而不是换一个方向，我们还要花 5 年时间，才可以深入到一定水平。

当然，技术深度和技术广度，往往是相辅相成的，相互反哺。

而合格的 40 岁开发者，必须已经完整的具备了高效学习的能力。可以快速接受新的技术方案，这也是两个年龄段最大的一个区别。

## 总结

我们在做职业规划时，实际上，就是在有意识、有方向的培养自己。这必然是一个需要损耗精力的事情。所以挺多人不愿意在这个方向花巨大精力去思考。

但是我们一定要记住，40岁开发者的终极竞争力，就藏在30岁时埋下的时间胶囊里。
